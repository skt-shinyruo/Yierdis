# 0005: 应用客户端用 Netty 异步提交命令

日期：2026-10-08
状态：Accepted

应用客户端不再用阻塞 `Socket` 读回复。一条连接是 Netty 上的命令通道：提交在事件循环接受写出之后返回 `CompletableFuture`，接受之前的失败在调用方线程抛出；回复按提交顺序在事件循环上配对。这扩大了 ADR 0002 里「只依赖 RESP 编解码」的依赖范围，`yierdis-client` 另外依赖 Netty。模块仍然独立，也不以官方 Jedis 兼容为目标。CLI 继续用自己的阻塞传输。

阻塞门面曾是候选，但留不住调用方线程上的读回复。管道不再是一种连接模式；未配对命令就是连接的普通状态。超时从写出算到调用方拿到的 Future 完成，事务命令算到 `EXEC` 的结果，不是 `QUEUED`；超时只失败那一条，晚到的回复仍由它消化。事务在 `MULTI` 提交时开始，命令结果在 `EXEC` 时完成。通道处于高水位、不可写时，在写出前拒绝这一条，不在内存里无界排队。默认一个 IO 线程，可由连接设置调整；池里的连接共用池的事件循环组。不能和server共用的入站预算、执行请求不抽到客户端。
